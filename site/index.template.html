API

One function, MuscleMap.createMuscleMap(svg, options), returns a controller. Create it once per inline SVG.

multiple

Tap toggles a muscle and keeps the others. Default is one selection.

bilateral

Left and right select together. Keys become both:muscle_id.

onSelect(region)

Fires per tap with muscleId, side, view, selected and the full region metadata.

onChange(selected)

The logical selection, one entry per muscle, not per drawn tile.

setSelected(keys)

Select from code, for example ['right:lateral_deltoid'].

setView('both' | 'front' | 'rear')

Switch the visible side.

setColors(values)

Heatmap. { lateral_deltoid: 0.8, biceps_brachii: '#2dd4bf' }: a number from 0 to 1 is blended from blue to red (override with { low, high }), a string is used as a CSS colour. Selected muscles keep the selection colour. clearColors() removes them.

clear() destroy()

Clear the selection, or remove the listeners before rebinding.

--muscle-active

CSS variable for the selected fill. --muscle-hover and --muscle-focus cover the other states.

Anatomical right is screen-left in the front view and screen-right in the rear view. The side metadata already accounts for this, so do not flip the SVGs horizontally. TypeScript types are in muscle-map.d.ts.

Muscle IDs

Use muscleId to connect a tap to your own data, for example an exercise catalog. The IDs are the same on both bodies and both views.

{{MUSCLE_ROWS}}
NameIDGroupTypeSelectable

Boundaries are simplified for a fitness diagram, not a dissection atlas. Forearm flexors and extensors, hip adductors, medial hamstrings, fibularis muscles and the lumbar erectors are groups because the artwork cannot separate the individual muscles. Knee, tendon and fascia panels are drawn but not selectable. See the verification notes for what is source-backed and what is not.
